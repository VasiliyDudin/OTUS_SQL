# 🌿 Plant World — База данных для сервиса доставки и ухода за растениями

Проект представляет собой реляционную базу данных для онлайн-сервиса по продаже, доставке и уходу за уникальными растениями из знаменитых мировых локаций (Эйфелева башня, Памуккале, парки Китая, Сикстинская капелла и др.).

---

## 📖 Описание проекта

Сервис позволяет:
- Продавать растения (семена, саженцы, взрослые экземпляры)
- Оформлять доставку по городу / региону
- Предоставлять услуги по уходу и выращиванию
- Консультировать по климатическим условиям и адаптации растений

База данных охватывает полный бизнес-цикл: ведение ботанического справочника, управление клиентами, сотрудниками, заказами, логистикой и складским учётом.

---

## 🧱 Структура базы данных

### Основные таблицы

| Таблица | Назначение |
|---------|------------|
| `Attraction` | Уникальные мировые локации (достопримечательности) с географическими координатами |
| `Location_address` | Детальные адреса локаций с почтовыми индексами и координатами |
| `Plant_directory` | Ботанический справочник видов растений |
| `Plant_characteristics` | Характеристики растений (свет, полив, температура и др.) |
| `Instructions_care` | Инструкции по уходу за растениями |
| `Products` | Товарные позиции с ценами, остатками и артикулами |
| `Orders_Products` | Связующая таблица «заказы → товары» (многие ко многим) |
| `Orders` | Основной документ заказа |
| `Customers` | Клиенты (физические и юридические лица) |
| `Delivery` | Способы доставки |
| `Logistics` | Маршруты и логистика доставки |
| `Employees` | Сотрудники компании |

### Связи между таблицами

- `Plant_directory` → `Location_address` → `Attraction` (место происхождения)
- `Products` → `Plant_directory` (вид растения)
- `Orders_Products` → `Orders` и `Products` (состав заказа)
- `Orders` → `Customers`, `Delivery`, `Employees` (клиент, способ доставки, ответственный сотрудник)
- `Logistics` → `Orders`, `Employees` (логистика и курьеры)

## ⚙️ Оптимизация производительности

Для ускорения работы с базой данных созданы индексы двух типов:

### B-tree индексы
Для полей внешних ключей и часто используемых атрибутов:
- `Location_address(Attraction_id)`
- `Plant_directory(Origin_location_id)`
- `Plant_characteristics(Plant_id)`
- `Instructions_care(Plant_id)`
- `Products(Plant_id)`, `Products(Article_number)`
- `Orders(Customer_id)`, `Orders(Delivery_id)`, `Orders(Assigned_employee_id)`
- `Orders_Products(Orders_id)`, `Orders_Products(Products_id)`
- `Logistics(Order_id)`, `Logistics(Employee_id)`

### GIST-индексы (для PostGIS)
Для пространственных полей:
- `Attraction(Coordinates)`, `Attraction(Center_point)`
- `Location_address(Point)`
- `Logistics(Start_point)`, `Logistics(End_point)`, `Logistics(Route_geometry)`

## 📊 Представления (VIEW)

Для удобства аналитики и построения дашбордов созданы следующие представления:

| Представление | Назначение |
|---------------|------------|
| `v_sales_performance` | Эффективность продаж: ТОП растений по выручке, остатки на складе, статус закупки |
| `v_active_customers` | Активные клиенты: контакты, история заказов, сумма покупок, статус активности |
| `v_plant_inventory` | Складской учёт: количество видов, остатки, диапазон цен, характеристики |
| `v_company_dashboard` | Сводная статистика: клиенты, заказы, выручка, товары, сотрудники |

|---------|------------|
| `get_delivery_details_by_order` | Детали доставки по ID заказа: стоимость, сотрудник, оплата, логистика |

## 📦 Хранимые процедуры

Для загрузки данных и управления заказами созданы процедуры:

| Процедура | Назначение |
|-----------|------------|
| `load_plants_from_csv` | Загрузка справочника растений из CSV-файла |
| `load_employees_from_csv` | Загрузка справочника сотрудников из CSV-файла |
| `load_customers_from_csv` | Загрузка справочника клиентов из CSV-файла |
| `update_order` | Универсальное обновление заказа с логированием изменений |
| `proc_recalc_order_total` | Пересчёт итоговой суммы заказа |

---

## ⚡ Триггеры

Автоматизация бизнес-логики реализована через триггеры:

| Триггер | Таблица | Событие | Назначение |
|---------|---------|---------|------------|
| `trg_recalc_after_insert` | `Orders_Products` | `AFTER INSERT` | Пересчёт суммы заказа при добавлении товара |
| `trg_recalc_after_delete` | `Orders_Products` | `AFTER DELETE` | Пересчёт суммы заказа при удалении товара |
| `trg_recalc_on_delivery_change` | `Orders` | `AFTER UPDATE OF Delivery_id` | Пересчёт суммы при смене способа доставки |

Все триггеры используют общую функцию-обёртку `recalc_order_total()`.

## 📈 Визуализация в Metabase

Для визуализации данных используется **Metabase**. Созданы дашборды:

- **Складской учёт** — остатки, цены, статус товаров
- **Клиентская аналитика** — активность клиентов, сегментация, ТОП-клиенты
- **Эффективность продаж** — выручка по растениям и семействам
- **Общая статистика компании** — ключевые KPI

## 🧰 Технологический стек
